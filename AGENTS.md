# Инструкции для Codex

Это legacy VB.NET-проект для Topomatic/CAD на .NET Framework 4.8.

Главный агент является координатором. Отдельного агента-оркестратора
создавать не нужно.

## Основной принцип

Сохраняй существующее поведение проекта.

Не изменяй код, если пользователь попросил только анализ, объяснение
или диагностику.

Перед редактированием сообщи:
- подтвержденную причину;
- какие файлы потребуется изменить;
- какие проверки будут выполнены.

## Роли

Используй `bug_researcher` для диагностики. Он работает только на чтение.

Используй `test_writer` для создания тестов, фиксирующих существующее
поведение. Он не должен редактировать производственный код.

Используй `implementer` для минимального подтвержденного исправления.

Используй `reviewer` для независимой проверки готового diff.
Он работает только на чтение.

Используй `verifier` для сборки, тестов и подготовки ручной проверки
в Topomatic.

## Исправление ошибки

Работай последовательно:

1. `bug_researcher` исследует проблему.
2. Главный агент проверяет его вывод.
3. `test_writer` создает воспроизводящий или characterization-тест.
4. `implementer` вносит минимальное исправление.
5. `reviewer` проверяет diff.
6. `verifier` выполняет сборку и тесты.
7. Главный агент собирает результаты и сообщает пользователю итог.

## Рефакторинг

Перед рефакторингом:

1. Зафиксируй текущее поведение тестами.
2. Изменяй небольшую область за один раз.
3. Не смешивай рефакторинг с исправлением других ошибок.
4. После каждого этапа выполняй независимую проверку.

## Параллельная работа

Параллельно разрешается выполнять только независимые задачи.

Можно параллельно:
- исследовать разные подсистемы;
- проверять разные файлы;
- изучать тестовые сценарии.

Нельзя:
- разрешать двум агентам редактировать один файл;
- одновременно запускать двух агентов-разработчиков;
- редактировать производственный код и тесты без согласования ожидаемого поведения.

Агенты, изменяющие файлы, работают последовательно.

## Ограничения проекта

- Сохраняй кодировку и BOM существующих VB.NET-файлов.
- Не изменяй публичные сигнатуры без необходимости.
- Не изменяй форматы XML, JSON и plugin-файлов без явного разрешения.
- Не удаляй существующие пользовательские изменения.
- Для сборки используй Visual Studio MSBuild.exe.
- Не считай успешную сборку полноценной проверкой CAD-геометрии.
- Геометрию, Topomatic API и COM-интеграцию проверяй отдельно.

## Выбор уровня рассуждений агентов

Главный агент выбирает `model_reasoning_effort` перед запуском агента
в зависимости от сложности конкретной задачи.

Используй:
- `medium` — для сборки, запуска тестов и простых проверок;
- `high` — для обычной диагностики, написания тестов и исправлений;
- `xhigh` — для неоднозначных ошибок, CAD-геометрии, матриц,
  преобразований координат, COM/Topomatic API и независимого review;
- `ultra` — только для исключительно сложных задач, когда `xhigh`
  недостаточно, либо по прямому указанию пользователя.

Не используй `xhigh` и `ultra` для механических операций.
