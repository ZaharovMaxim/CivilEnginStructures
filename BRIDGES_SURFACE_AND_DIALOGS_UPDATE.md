# Обновление модели «Мосты», поверхности и диалогов

## Установка

1. Сохранить текущий проект и закрыть Topomatic Robur Road 16.0.
2. Сделать резервную копию текущих DLL и plugin-файлов Infrastrada, а также всего рабочего проекта, который будет открыт после обновления.
3. Скопировать из подготовленного комплекта в каталог установки Topomatic:
   - `CivilEnginStructures.dll`;
   - `CivilEnginStructures.pdb` рядом с DLL для отображения файла и строки в технических деталях ошибок;
   - `InfrastradaBridgeTools.plugin`;
   - `y_InfrastradaRoadTools.plugin`;
   - каталог `Icons` с сохранением структуры и заменой файлов из комплекта.
4. Не заменять штатный `ribbon.surface.plugin`: собственный plugin-файл ссылается на его 12 штатных контекстов поверхности.
5. Запустить Topomatic и выполнить сценарий из `BRIDGES_MODEL_MANUAL_CHECKLIST.md` на копии проекта.

## Что изменилось

- Модель «Мосты» использует нативную поверхность Topomatic и один канонический `Drawing` для CAD-объектов.
- Балки, опоры, монолит и конусы работают с этой моделью; конусы создаются непосредственно на поверхности модели «Мосты».
- Собственная вкладка модели включает 12 штатных панелей поверхности. Нативные структурные линии редактируются отдельно от DWG-групп сооружений.
- Закрытый мост представлен одним контейнером: обычный и `Shift`-щелчок не показывают отдельные элементы. Вход выполняется через контекстную команду **Редактировать мост**, после чего доступны штатная группа и `Shift + щелчок` отдельного элемента. Команда **Завершить редактирование моста** возвращает закрытый контейнер.
- В плане пространства модели скрываются рёбра только у помеченных 3D-тел моста. Сами тела сохраняются для 3D-вида; поведение листов и печати требует ручной проверки.
- На ленту добавлено **Оформление моста**: цвет CAD, слой, тип и масштаб линии, толщина, ширина полилинии и независимый цвет 3D-тела на уровне моста, класса, типа или элемента. Смешанное поле без выбранного нового значения не перезаписывается.
- Оформление однозначно сопоставимых элементов восстанавливается после перестроения. Однородный цвет переносится на изменившееся количество 3D-тел; неоднородные цвета не назначаются новым телам по порядковому номеру.
- Проектная поверхность дороги и поверхность земли ЦММ остаются внешними hard references. Site в модель «Мосты» не импортируется.
- Обновлены формы **Конусы**, **Участки омоноличивания** и **Библиотеки** с поддержкой изменения размера окна и масштабирования интерфейса.
- Ошибки построения показывают операцию, этап, причину, действие и технические детали. Журнал записывается в `%LOCALAPPDATA%\Infrastrada\Logs\bridge-build-errors.txt`; подходящий PDB добавляет исходный файл и строку.
- Исправлено падение окна **Настройки мостов** с ошибкой `SelectedIndex` при открытии. Недоступная сохранённая ссылка показывается отдельно и не заменяется случайным значением.
- Контейнер и редактор оформления находят мост по метке его идентификатора даже без отдельного элемента оси. При отсутствии читаемой оси контейнер подписывается идентификатором; полные название и характеристики можно получить только из сохранённых данных оси.
- Контекст команд берётся из текущей активной модели. При нескольких открытых моделях сначала используйте **Сделать текущим**; выделения узла в дереве проекта недостаточно.
- Кнопка **Объединить мосты** удалена с ленты: контейнер создаётся автоматически. Ошибки команд настроек, оформления и совместимой команды группировки показываются через диагностическое окно плагина.

Подробная работа контейнера, оформления и диагностики описана в `BRIDGES_CONTAINER_APPEARANCE_ERRORS.md`.

## Совместимость файлов

Новая версия открывает старые `.infrabridgex` на основе Arrangement. При первом сохранении такого файла рядом создаётся резервная копия с суффиксом `.legacy-arrangement.bak`, после чего основной файл записывается в новом нативном формате. Сохранить эту копию до окончания ручной проверки. Нельзя исходить из того, что старая DLL сможет открыть файл, уже сохранённый в новом формате.

Финальная автоматическая проверка от 30.09.2026 выполнена Visual Studio MSBuild для Debug и Release. В x64-прогоне без `TopomaticIntegration` прошли 400 из 400 запущенных тестов; один `Explicit` офлайн-визуальный тест пропущен обычным прогоном.

Сборка и обычные автоматические тесты подтверждают компиляцию и проверяемые программные контракты. Они не подтверждают правильность CAD-геометрии, реальное поведение Topomatic API/COM, группового выделения, 3D-вида, Undo, печати и нативного сохранения; для выпуска обязательна ручная проверка в Topomatic.

## Дополнение fix2: раскладка и пересчёт

- Исправлена передача отступа ряда и толщины покрытия из траектории в сохранённые данные балки. При повторном открытии окна из общих смещений выделяются локальные значения ряда, без повторного прибавления смещения моста.
- Свойства сооружения из боковой палитры сохраняются с числовыми типами. Изменение поперечного и вертикального смещения переносится в данные балок на разницу старого и нового значения.
- Число пролётов и рядов слева/справа видно в палитре, но изменить его можно только в окне раскладки. Новые ряды требуют назначения балок в этом окне.
- Левый щелчок по «Пересчёт» перестраивает выбранное сооружение; правый щелчок открывает меню. При выбранном дочернем элементе определяется его сооружение. После успешного пересчёта дерево и свойства обновляются.
- В окно раскладки добавлено продольное смещение в миллиметрах. В боковой палитре значения смещений остаются в метрах. Продольное положение рассчитывается от сохранённого начального пикета; повторный пересчёт не должен накапливать сдвиг.
- Отметки балок при пересчёте определяются по проектной поверхности в новых координатах. Неудачный расчёт отметок останавливается с указанием пролёта и ряда. Часть геометрии к этому моменту могла измениться: подробности содержит окно диагностики.
- Исправлены идентификаторы и координаты осей опирания соседних пролётов, которые приводили к пропаданию осей после повторного построения.
- После успешной раскладки неназначенная проектная поверхность модели инициализируется выбранной поверхностью или поверхностью трассы. Уже заданная настройка не перезаписывается. Поверхность земли автоматически не назначается.
- Список поверхностей окна «Настройки мостов» формируется по ссылкам проекта без предварительной загрузки содержимого посторонних моделей.
- Старые обнулённые параметры автоматически не восстанавливаются. По уточнению пользователя используются тестовые модели; проверка выполняется на новой раскладке.

Отчёты Excel не изменены: перед выбором отчёта нужно выбрать само сооружение в дереве боковой палитры.

## Каталог дополнительных ресурсов

На проверяемом компьютере каталог ресурсов расположен в `C:\InfrastradaToolsUtility`. Он существует и содержит библиотеки `TopomaticRobur\DesignBridge\Beams`, `Pillars`, `UserProperties`, а также `FileResources\Sample` и `FileResources\SHPForms`.

В команде «Настройка программы» выбирается корень `C:\InfrastradaToolsUtility`; команда добавляет вспомогательные пути из него. Обновление fix2 не меняет файлы этого каталога. DLL, PDB, plugin-файлы и Icons устанавливаются по пунктам раздела «Установка» в каталог установки Topomatic.

Финальная проверка fix2: Visual Studio MSBuild Debug и Release — без ошибок сборки; полный автономный прогон x64 — 400 из 400 выполненных тестов успешно. Первый запуск тестов использовал лишний уровень `bin\x64` и не нашёл часть файлов проекта; после сборки тестов в штатный `bin\Debug\net48` полный прогон прошёл. Производственный код для исправления пути запуска тестов не менялся.
